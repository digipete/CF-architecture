# Guardrails

Guardrails define the safe operating space for an experiment without prescribing every implementation choice.

Useful guardrails may cover:

- permitted users or cohorts
- data that can and cannot be used
- environments and integrations
- transaction or volume limits
- manual oversight
- security and privacy controls
- operational support
- time limits
- escalation and stop conditions

A guardrail should have a clear reason. Avoid reproducing full production governance when the experiment does not create production-level exposure.
