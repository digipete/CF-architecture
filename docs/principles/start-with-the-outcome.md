# Start with the outcome

<p class="cf-lede">Understand the problem before choosing the technology.</p>

<div class="cf-panel cf-panel--principle"><strong>Principle</strong>Understand the problem before choosing the technology.</div>

## Why this matters

Technology choices should follow from understanding the outcome, users, operating context, constraints and evidence. Starting with a product, platform or technical preference risks optimising the wrong thing.

## What this means in practice

Use this principle to make the decision smaller, clearer and easier to revisit as evidence changes.

## Questions to ask

- What outcome are we trying to change?
- Who experiences the problem today?
- What would be measurably better?
- Which constraints are real, and which are assumptions?

## During a Test & Learn Experiment

Use the experiment to learn whether the proposed intervention changes the outcome. Avoid turning the experiment into a test of a technology simply because that technology is available.

## Watch out for

- Solutions looking for problems
- Treating an existing product as the requirement
- Optimising a technical component rather than the whole service
